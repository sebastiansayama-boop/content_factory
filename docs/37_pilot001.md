# Content Factory Pilot001

## Goal

Pilot001 is the first product-level Content Factory experiment. It is not an infrastructure proof.

The user supplies a direction through Telegram. The factory then:

1. researches current signals from public news RSS;
2. selects a content angle with a local model;
3. writes a social post;
4. creates a 4-7 slide carousel;
5. renders local PNG slide assets;
6. sends the draft to Telegram;
7. exposes Approve / Regenerate / Reject controls;
8. stops at the human publication boundary.

The user manually publishes the approved package to Instagram / Threads for Pilot001.

## Free local stack

- Telegram Bot API for the human interface and review controls.
- Google News RSS for current research signals.
- Ollama local API for model execution.
- Qwen3 8B is the default local model and can be replaced with `OLLAMA_MODEL`.
- Pillow renders the carousel images locally.

Ollama documents a local HTTP API on `localhost:11434`; the current Ollama library lists `qwen3:8b` as a 5.2GB model. Telegram's Bot API supports `getUpdates`, inline keyboards/callback queries, `sendPhoto`, and message editing. 

## Run

Prerequisites:

```powershell
ollama pull qwen3:8b
```

Environment:

```powershell
$env:TELEGRAM_BOT_TOKEN="<BOT_TOKEN>"
$env:TELEGRAM_CHAT_ID="<YOUR_CHAT_ID>"
$env:OLLAMA_MODEL="qwen3:8b"
```

Start the pilot:

```powershell
cd C:\Users\sebas\content_factory
uv sync --extra dev
uv run python scripts/run_pilot001.py
```

Then send the bot:

```text
/pilot AI agents for small businesses
```

## Telegram review lifecycle

```text
/pilot <direction>
      ↓
research
      ↓
local model
      ↓
post + carousel
      ↓
Telegram preview
      ├── Approve
      ├── Regenerate
      └── Reject
```

Approve means the content is approved for manual publication. Pilot001 intentionally does not automate Instagram / Threads publication yet.

## What Pilot001 proves

This pilot is intended to prove a useful product loop rather than infrastructure transport:

- a human can set a direction;
- the factory can retrieve current signals without a paid research API;
- a local model can transform those signals into a content package;
- carousel assets are actually generated;
- the user can review the result in Telegram;
- the user can ask for a new generation without rebuilding the task manually;
- approval remains a human boundary.

It does not yet prove automated publication, long-horizon planning, audience-performance feedback, or autonomous learning.
