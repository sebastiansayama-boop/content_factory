# User Sector 1 — Source to Reviewable Content Package

## Product sector

A real user can:

1. open Content Factory;
2. paste a substantive source and optional title;
3. analyze the source;
4. inspect summary, themes, stories, moments, and source evidence;
5. select one story angle;
6. choose text content formats;
7. generate a linked content package;
8. review and edit the generated assets;
9. copy a final asset for use outside the factory.

## Scope

Included: text source input, AI analysis, explicit story selection, article, social posts, long-form video script, short-video script, evidence references, inline editing, clipboard export.

Excluded: transcription, media generation, external publishing, scheduling, accounts, billing.

## User-value hypothesis

A user with substantive source material can turn one source into a coherent multi-format content package faster than producing each asset independently, while retaining visibility into the selected story and source evidence.

## Test gate

The sector is not considered successful because the code or automated tests pass. A user test must observe:

- task completion without developer intervention;
- whether the user understands the Source → Explore → Produce flow;
- whether the user can identify and select a useful story;
- whether generated assets are considered usable;
- whether source references increase or decrease trust;
- what the user edits or rejects;
- where the user becomes blocked or confused.

## Technical gate

The public beta path must use the real production AI provider and the existing executable factory runtime. It must not use demo fixtures, fake providers, synthetic publication, or mocked external execution.

## Evidence boundary

A successful user task is evidence about usability and perceived value for that tested case. It is not evidence of market demand, retention, willingness to pay, or general product-market fit.
